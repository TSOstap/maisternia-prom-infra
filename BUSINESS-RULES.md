# Фактична бізнес-логіка чинної системи

Джерело — живі копії Apps Script від власника, отримані Codex 21.10.2026. Байт-у-байт копії лежать у `reference/apps-script-live/`, SHA-256 — у `reference/README.md`. Нижче лише те, що прямо видно в коді. Посилання ведуть на рядки цих копій.

Позначки: **[ФАКТ]** — видно в коді. **[ПАРИТЕТ]** — у прототипі перевірено тестом, який запускає справжній LIVE-код у VM. **[НЕ ПЕРЕВІРЕНО]** — потребує живих даних або Google runtime.

## 2. Ціноутворення [ФАКТ][ПАРИТЕТ]

`extra=5, markup=0.25, discount=20, rounding=0.01` (Code.LIVE:5, 12-16):

- `Final = round2(ціна_постачальника + 5)`;
- `Base = round2(round(Final × 1.25 / 0.01) × 0.01)`;
- `available=true` → знижка «20%», наявність «+»; `false` → знижка '', наявність «-»;
- у YML: якщо товар є в наявності, `<price>`=Final і `<oldprice>`=Base; якщо немає, `<price>`=Base без oldprice (Yml.LIVE:142-143);
- знижка «20%» і число 0.2 вважаються однаковими (допуск 1e-9). Інші подання («0,2», « 20%», 20) — ні (Code.LIVE:69-79).

Самоперевірка: ціна постачальника 100 → Final 105, Base 131.25 (Code.LIVE:258).

## 3. Зіставлення Offer ID → offer постачальника [ФАКТ][ПАРИТЕТ]

Рядок шукається за «ID постачальника». Перевірки йдуть по черзі, спрацьовує перший провал (Code.LIVE:50-66):

1. offer відсутній у фіді → `ВІДСУТНІЙ_У_YML`;
2. ID не збігається → `КОНФЛІКТ_ID`;
3. артикули після нормалізації (розбити за комою, обрізати, відсортувати) різні → `КОНФЛІКТ_АРТИКУЛА`. Якщо артикула немає, обов'язкові точний URL та обидві опорні назви;
4. збережена опорна назва UA або RU не збігається після NFKC, нижнього регістру й стиснення пробілів → `ЗМІНА_ІДЕНТИЧНОСТІ_АБО_КОМПЛЕКТУ`;
5. немає жодної опорної назви → `НЕМАЄ_ОПОРНОЇ_НАЗВИ`;
6. валюта не UAH → `НЕВІДОМА_ВАЛЮТА`; ціна ≤0 або не число → `НЕВАЛІДНА_ЦІНА`; атрибут `available` не true/false → `НЕВІДОМА_НАЯВНІСТЬ`; кількість не число → `НЕВАЛІДНА_КІЛЬКІСТЬ`;
7. інакше → `ЗІСТАВЛЕНО`.

## 4. Що записується в F:M [ФАКТ][ПАРИТЕТ]

Code.LIVE:87-107:

- **ЗІСТАВЛЕНО**: нові ціна постачальника, Base, Final, знижка, наявність. Кількість: якщо в постачальника порожньо, лишається попередня. Стан і час оновлюються;
- **ВІДСУТНІЙ_У_YML** (повний здоровий фід доводить відсутність): стара ціна зберігається, знижка '', наявність «-», кількість '', стан, час;
- **будь-який конфлікт або невалідне значення**: ціни й наявність НЕ змінюються, оновлюються лише стан і час.

## 5. Формування YML (mtBuildYml_) [ФАКТ][ПАРИТЕТ — байт-у-байт]

Yml.LIVE:102-169:

- у фід потрапляє лише «Основний каталог»; «Нові товари» синхронізуються, але не експортуються;
- `TOOLS_SYNC_STATE=OK`, останній успіх не старший за 12 год;
- **набір вшитий у код (MTY)**: `count=5029`, `idsSha`, `contentSha`, `groupsSha` (Yml.LIVE:2-11). Будь-яке додавання чи видалення товару вимагає зміни коду;
- печатка рядка: `SHA256(JSON.stringify({незмінні колонки: mtText(v)}))`. Незмінні колонки — 31 колонка з MTY.headers без F:M і без самої печатки. Печатка мусить збігатися з колонкою «SHA256 незмінних полів»;
- `contentSha` — SHA відсортованих рядків `id\tпечатка`. `groupsSha` — SHA канонічних груп, відсортованих за ID;
- **кожен рядок** повинен мати «Статус імпорту»=ДОЗВОЛЕНО, «Стан синхронізації»=ЗІСТАВЛЕНО і «Оновлено» рівно з часом останнього успіху (Yml.LIVE:132-133);
- ціни в рядку перераховуються формулою і звіряються; назви й описи UA/RU не можуть бути порожніми; фото — від 1 до 10; характеристик — не більше 100; запити — не довші за 1024 символи;
- `<vendorCode>` береться з «Код товару Prom», а не з артикула постачальника. `type=vendor.model` не задається;
- ліміт **50 000 000 байтів UTF-8**. Секретні шаблони (`hash_tag=`, `products_feed.xml`, `Bearer …`) зупиняють формування;
- `sourceDigest` — SHA усього XML без атрибута date. Якщо він не змінився, новий файл не створюється.

## 6. Публікація і роздача [ФАКТ]

Yml.LIVE:222-292:

- кандидат пишеться в Drive → readback SHA → перевіряється, чи не змінилося джерело → **один запис** `TOOLS_YML_ACTIVE` перемикає `{active, previous}`. Старші версії йдуть у кошик Drive;
- `doGet` вимагає `?key=` (`TOOLS_YML_ACCESS_KEY`). Читає active і на кожен GET перевіряє SHA. Якщо active пошкоджений, віддає previous. Якщо немає жодного — помилка, не порожній каталог;
- постійна адреса — `/exec?key=…` вебзастосунку Apps Script.

## 8. Що не видно з коду [НЕ ПЕРЕВІРЕНО]

- Фактичні значення Script Properties і тригер. Вміст робочої таблиці звірено лише за xlsx-експортом 21.10 (DATA-AUDIT-20261021.md): печатки, хеші, F:M і YML збіглися з LIVE.
- Як типізує клітинки саме Sheets API (`UNFORMATTED_VALUE`). xlsx-експорт дав ті самі печатки, що getValues, але API ще не перевірявся (CONNECT-PLAN.md, C2-B).
- Налаштування імпорту в кабінеті Prom: «товари, яких немає у файлі», розклад.
- За експортом 21.10 черга «Нові товари» вже містить 92 рядки, що точно відповідають NEW92 Codex. Чи встановлено код другого фіду і чи імпортовано 92 у Prom, з даних не видно: в експорті Prom від 21.10 01:07 їх немає. Нова система будує фід new92 з тих самих даних (shadow-replay, 915 267 Б).
