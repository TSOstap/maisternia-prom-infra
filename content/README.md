## Порядок пріоритету джерел

Якщо джерела суперечать, діє вищий рівень. На одному рівні — новіше за датою.

1. **Найновіші рішення власника** — `OWNER-DECISIONS.md` (зверху — 03.11.2026).
2. **Тексти й винятки власника** — `Матеріали\Описи\Тексти власника\партія-NN.txt`, `Матеріали\Описи\Винятки власника\винятки-власника.json`.
3. **Шаблон T-1.0** (затверджена редакція 29.10) — `templates\T-1.0\`.
4. **Стандарти Claude Content** — контракт L3 (07.10), архітектура V3 (02.10), Stage 9 V2.x — у частині, не скасованій рівнями 1–3.
5. **Загальні правила** — `RULES.md`, розд. 0; правила користувача (не вигадувати, не робити зайвого).

Нерозв'язну суперечність не вирішувати самостійно: записати в `OPEN-QUESTIONS.md` і спитати власника.

## Як користуватися

1. Перед роботою з товаром: знайти Offer ID у покажчику `OWNER-DECISIONS.md` і в `OPEN-QUESTIONS.md`. Є відкрите питання — товар не затверджувати.
2. Робота — за `RULES.md` (розділи 1–8 за типом поля).
3. Опис: каркас `templates\T-1.0\skeleton.*.html`, еталон `templates\T-1.0\example-3062703455.*.html`.
4. Перевірка опису:
   ```
   node content/tools/check-description.mjs <ua.html> <ru.html> [<джерело.txt> <рядок від> <рядок до>] --offer=<Offer ID> --exceptions="E:\Prom Maisternia Market\Матеріали\Описи\Винятки власника\винятки-власника.json"
   ```
   Лише читає файли. Код виходу 1 — є FAIL. Параметри `--offer` і `--exceptions` — лише разом.
5. Перед записом — чек-лист `RULES.md` розд. 9.2; після — 9.3.
6. Нове рішення власника → рядок у `OWNER-DECISIONS.md` (з датою й джерелом) → правка відповідного розділу `RULES.md` (старе — у примітку «Скасовано»).
