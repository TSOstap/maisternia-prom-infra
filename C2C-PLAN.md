## 2. Час: XML проти mtUpdate

Факт із журналу: дата фіду постачальника дорівнює хвилині запиту (mtUpdate о 13:20 UTC отримав `date="… 16:20"` Київ). Фід генерується «на льоту», тож **знімка, ідентичного тому, який бачив mtUpdate, отримати неможливо**. Тому:

| Режим | Коли | Висновок |
|---|---|---|
| SAME_SNAPSHOT | дата фіду = `feedDate` останнього mtUpdate | будь-яка різниця F:K = **LOGIC_DIFF** |
| NEWER_FEED (очікуваний) | фід пізніший | групи колонок перевіряються **окремо** за своїми входами: [F,G,H] ← ціна постачальника, [I,J] ← available, [K] ← кількість. Незмінний вхід → група мусить збігтися, інакше LOGIC_DIFF (зміна кількості не ховає помилку в Base). Статус нової системи звіряється зі статусом у таблиці: однаковий не-OK статус → UNCHANGED; зникнення → SUPPLIER_REMOVED; інший статус → STATUS_CHANGE; не-OK → OK → RECOVERED. Зміни входів — SUPPLIER_CHANGE (ціна ↑/↓, наявність, кількість) |
| OLDER_FEED / UNKNOWN | фід старіший; у журналі немає успішного mtUpdate; мітка «Оновлено» рядків ≠ журнал | порівняння з таблицею **не дає висновку** про логіку: усе змінене = UNCONFIRMED, перевірка «порівняння достовірне» = FAIL. Паритет LIVE на тому самому XML лишається достовірним |

Додатково:
- **NOT_SYNCED_YET** — рядки з порожнім або іншим «Оновлено», ніж останній mtUpdate у журналі; вони не порівнюються.
- **Покриття** — частка порівнюваних рядків, перевірених за незмінними входами. Перевірка вимагає ≥50%, інакше «0 розбіжностей» нічого не доводить.
- **Обсяг фіду.** Відхилення від `offers` останнього mtUpdate на понад max(20, 1%) у NEWER_FEED — лише **попередження**: це може бути нормальний дрейф асортименту або інше посилання, ніж `TOOLS_FEED_URL` LIVE. Жорстка перевірка — тільки для SAME_SNAPSHOT.
- **Коди виходу:** 0 PASS · 1 FAIL · 2 помилка читання/доступу · 3 спрацював захист від витоку · 4 висновок неможливий (немає синхронізованого знімка).

## 3. Захист від витоку (п. 8)

- У вивід, Job Summary і код виходу потрапляють **лише агрегати**. Offer ID, назв, цін окремих товарів і текстів немає (перевіряється тестом).
- **Вбудований захист — єдина функція виводу `emit()`** для stdout і stderr (окремо — для summary). Перевіряє фрагменти секретів: адреса постачальника; кожне значення параметра (як є і URL-закодоване); query-рядок; host+path+query; операційна адреса; ID таблиці; токен Google. Також блокує будь-яке число з 10+ цифр (форма Offer ID). Збіг → нічого не друкується, код 3 (тести з навмисним збігом).

- `::add-mask::` свідомо не використовується: рядок команди містив би похідне значення секрету, а поведінку його логування не перевірено.

- GitHub додатково маскує значення секретів у лозі; секрет постачальника передається **лише** кроку shadow-звірки.
